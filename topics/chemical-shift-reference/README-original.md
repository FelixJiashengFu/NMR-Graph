## 这一版做了什么

### 1. 原图的三处文字重叠，逐个拆开

原截图里这些地方的字是叠在一起的，读不出来：

- **¹H 的 3.4–6.1 ppm 带**：「强去屏蔽区：O-CH、端基氢、烯氢」两行 + 右邻格标题挤在同一高度；
- **¹³C 的 48–75 ppm 带**：「甲氧基」「季碳」「烷基 CH₂/CH」「伯碳区」四段互相压叠，出现「甲氧基羰基季碳」这种串字；
- **¹³C 右端**：「烷基 CH2 / CH 区」两行与邻格标题重叠。

**处理**：色块里只留一行短标签（自动换行，绝不溢出），完整名称与 ppm 区间放到色块下方的图例里；
被压叠到读不出的三格，按标准区间校订后在页面上明确标注「校订」，不假装是从原图读出来的。

### 2. 每个分区都配结构式

15 张结构式全部是**手写的内联 SVG**（不是图片、不是 emoji），包括：
醛 / 酮 / 羧酸 / 酯 / 酰胺 / 烯烃 / 末端炔 / 芳环 / 烷基 / 醇 / 胺 / 甲氧基，
外加三张"聚焦"式结构图（醛氢、芳氢、连氧碳上的氢）。

### 3. 横轴改成真比例尺

原图十个色块几乎等宽，但 2–4.6 ppm 那格和 8.2–10 ppm 那格跨度差好几倍。
本页横轴是**真比例 ppm 标尺**（¹H 全轴 14 ppm、¹³C 全轴 210 ppm），所以一格的宽度就是它的 ppm 宽度。

### 4. 联动

点色带分区 / 点结构卡片 / 点左栏条目 / 按 <kbd>1</kbd>–<kbd>9</kbd>，四种入口都会联动：
右栏给出读数、落在哪一格、为什么在那里、峰形提示。

## 验证记录

跑过的检查（全部可复现，脚本都在 _src/）：

1. **分区几何**：页内 `__selftest()` 51 项全过——分区首尾相接、无缝隙、重叠 ≤0.6 ppm、覆盖到轴末端、每个基团的区间都能找到所属分区。
2. **浏览器交互回归**：无头 Chrome 注入探针，**56 项断言全过、0 失败、0 页面错误**——覆盖色带渲染（10/11 格）、方向（最高 ppm 在最左）、15 张卡片、7 步引导、键盘、点击联动、以及"改 A 参数 B 不变"的组合用例。
3. **结构式几何**：离线解析 15 张 SVG 的全部 74 个文字/标记包围盒，无越界、无重叠。
4. **零外部加载**：正则扫描确认没有任何 http(s) 的 src/href。
5. **横向溢出**：1700px 与 1500px 视口下 `scrollWidth == clientWidth`。

开发过程中被验证抓出来的**真错误**（每个都是先有失败断言、才被发现的）：

| 错误 | 怎么被抓出来的 |
|---|---|
| 色带 ppm 方向画反（烷基跑到最左、极强氢键区跑到最右，整条谱镜像） | 加了"最高 ppm 分区必须在最左边"这条方向断言后立刻 FAIL |
| 术语加注脚本改写了会被重新渲染的容器，破坏 innerHTML，卡片只剩 11 张并抛 TypeError | 探针断言"卡片 15 张"FAIL + 捕获到 TypeError |
| 结构式标签与原子标记重叠 12 处 | 用无头 Chrome 量真实文字包围盒（不是按字数估算） |
| 工作台高度算得太早，底部留一大片空白 | 预览截图里肉眼看到，改成布局稳定后重量一次 |
| 分区映射过宽（点芳环点亮 5 格） | 交互断言按数据模型现场算格数后 FAIL |
| 图例标签把色带撑宽 245px | 逐元素量 scrollWidth，定位到 flex item 的 min-width:auto |

## 已知限制

- 所有 ppm 都是**常见区间**，不是保证值；取代基、溶剂、浓度、氢键都会把峰推走，碳谱尤其明显。
- 被压叠读不出的三格（¹H 的 2.6–3.4、1.76–2.6，¹³C 的 137.9–158）按教科书常用区间校订，页面上标了「校订 / 文献近似」。
- 结构式画的是**通用骨架**（R 基团），不是你手上那个分子。
- 本页不含任何真实谱图，色块不编码强度。
